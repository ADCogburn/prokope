# Review flag becomes per-lesson, not per-(student, subject)

For #76, the review flag needed to answer "does *this specific lesson* need extra support," including lessons the student has already passed or hasn't reached yet — something the existing `Progress.Review` boolean (one per student per subject, tied only to the student's current position) can't express. We're retiring `Progress.Review`/`ReviewHlc`/`ReviewClientId` (and the client-side `ProgressRow.review`/`review_hlc`/`review_client_id` fields) entirely in favor of a new flag keyed by `(student, lesson)`, and dropping existing flagged data outright rather than migrating it — there are no active users yet, so there's nothing to preserve.

One consequence worth flagging: because the flag now lives on the lesson rather than being derived from position, it does *not* auto-clear when a student advances past a flagged lesson. A flag persists until a teacher explicitly removes it — via the quick-toggle icon for the current lesson, or via Student Summary for any other lesson. The old per-subject model made "clear on advance" moot, since the flag was really only ever about the current lesson; the new model requires this to be a deliberate choice rather than an accident of the data shape.
