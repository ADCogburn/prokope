# AI Bulk Generation full-replaces a Subject's curriculum in one confirm step, with no undo

For #161 (AI Bulk Generation's output contract), the map (#157) and the "AI Bulk Generation" glossary entry both described the generated lesson list as flowing through "#143's propose/diff/accept-decline/replace/undo mechanism" before committing. That mechanism never existed: #143 was chartered independently as the unrelated, already-shipped "Bulk Generate" feature (a fixed-grid placeholder filler that only ever fills empty positions and commits immediately) — not the replace/diff/undo mechanism the map assumed it would become. No ticket ever specified what actually happens between a generated proposal and the database.

We resolved that gap here rather than leaving it open. When the teacher accepts a proposal, every existing live Lesson in the Subject is soft-deleted and the entire proposed list is inserted fresh — the AI's list becomes the Subject's whole curriculum, not a merge with what was there. This is a single all-or-nothing decision: one confirmation over the whole batch (matching #144's original "summarized confirmation modal, confirm/reject" framing), not a per-lesson diff. Per-lesson accept/decline doesn't hold up under full-replace anyway — declining one lesson wouldn't restore its prior content, since that content is gone regardless once the batch commits; the teacher can still edit or remove any individual lesson afterward with the existing single-lesson tools.

There is no post-commit "Undo" control. The pre-commit confirmation is the only safety net. A true undo would need to restore the wiped-out lessons (clear their `deleted_at`), and no restore/undelete function exists anywhere in `src/db/lessons.ts` today — #143 explicitly ruled that capability out of scope for Bulk Generate's own undo, which only ever deletes forward. Introducing first-of-its-kind restore logic for this one feature, on top of a destructive action the teacher already confirmed once, wasn't judged worth it for v1.
