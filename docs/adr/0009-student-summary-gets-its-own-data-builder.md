# Student Summary gets its own data builder, not a shared one with the print report

For #98 (Student Summary), the per-subject data it needs -- current lesson label, or "Not started"/"No lessons yet", plus review-flagged status -- is today identical in shape to what `buildStudentReport` already computes for the printable per-student report (#11). We considered just calling that function from the new page. We decided against it: the print report stays scope-frozen to #11, while Student Summary is explicitly meant to grow beyond "progress in all subjects" into future student-detail features. Sharing one data builder would couple that growth to whatever the print report needs, or vice versa. `buildStudentSummary` lives in its own `studentSummaryData.ts`, even though its output is effectively identical to `buildStudentReport`'s today.
