# AI Bulk Generation gets a two-tier rate limit, an explicit timeout, and minimal usage logging

For #160 (part of the AI Bulk Generation map, #157), `/ai-bulk-generation` is this codebase's first paid, per-request AI API call, and had no rate-limiting, timeout, or usage-tracking infrastructure at all. We added a two-tier rate limit rather than a single one: **20 generations/day per teacher**, kept in-memory (low stakes, resets naturally within a day, avoids a DB round-trip on every request), and a **100 generations/month global cap across all teachers**, persisted in Postgres and resetting on a calendar-month boundary — this is the limit actually guarding real Anthropic spend, so unlike the daily counter it must survive a Railway restart or redeploy mid-month. Exceeding either returns HTTP 429 with a message specific to which cap tripped, since the two imply different next actions for the teacher:

- Daily: "You've used all 20 AI generations for today — try again tomorrow."
- Monthly: "AI Bulk Generation has reached its limit for this month — try again next month."

We accept that a single teacher generating at their daily cap for five days straight could alone exhaust the whole month's shared budget, locking out every other teacher for the rest of the month. The app is pre-launch with very few real users, so this is unlikely to happen by accident, and solving it now — e.g. a per-user monthly sub-cap — would add a third limit tier for a problem with no usage data behind it yet.

Separately, the two sequential Anthropic calls in `AnthropicCurriculumClient` (see [ADR-0018](0018-anthropic-claude-two-call-web-search-for-ai-bulk-generation.md)) get an explicit deadline — roughly 30s for the search call, 60s for the extraction call — via a linked `CancellationTokenSource`, surfaced to the teacher as a clear timeout error. Previously nothing bounded a hung or slow call except the client disconnecting. No new plumbing was needed for the "teacher navigates away" case: the request's `CancellationToken` was already threaded through both Anthropic calls, so closing the tab or navigating away already cancels the in-flight request today. An explicit in-UI "Cancel" button was considered and deferred — out of scope for this ticket, owned by a separate issue.

For cost visibility, each call is recorded in a minimal structured application log (user id, timestamp, token counts) rather than a dedicated usage-tracking table — the monthly cap's counter table already provides persisted state for the one thing that needs it, and there's no billing/tier system yet to justify more.
