# Context: prokope

## Glossary

**Advance** — the Progress Cell control that moves a single student forward one lesson in a subject's curriculum. Bulk Advance extends this across every student in a class at once.

**Bulk Advance** — a teacher action on the Class Board that advances every student in a class one lesson at once, in a single click. Scoped to one subject: whichever subject is currently in focus on the Class Board's carousel (the panel at full opacity). Students already on that subject's last lesson (or a subject with no lessons) are silently skipped, matching the single-student advance button's existing behavior. See [ADR-0005](docs/adr/0005-bulk-progress-advance-is-scoped-to-one-subject.md).

**Un-advance** — the Progress Cell right-click menu option (see [ADR-0006](docs/adr/0006-right-click-for-progress-cell-options.md)) that moves a single student back one lesson — the inverse of Advance. Distinct from "Jump to lesson...", which can move a student to any position, including backward; Un-advance is a one-click shortcut for the common single-step case (see [ADR-0007](docs/adr/0007-un-advance-kept-separate-from-jump-to-lesson.md)). At the first lesson, un-advancing returns the student to "Not started."

**Review flag** — a per-lesson marker a teacher sets on a specific student's lesson as a reminder that the student needs extra support there. Independent of the student's current position: a flag can be set on the current lesson (toggled via the flag icon on the Progress Cell), or on any other lesson in that subject — past or upcoming — via the Progress Cell's right-click "Review other lessons" option. Flags persist until manually cleared; advancing past a flagged lesson does not clear it (see [ADR-0011](docs/adr/0011-review-flag-becomes-per-lesson.md)). Setting a flag on a lesson other than the current one is deliberately kept separate from "Jump to lesson..." (see [ADR-0012](docs/adr/0012-review-other-lessons-kept-separate-from-jump-to-lesson.md)). Not shown as a highlight on the Class Board subject panels; only the roster's per-student "X lessons marked for review" count and Student Summary's list of flagged lessons surface it.
_Avoid_: "flagged subject" (there is no subject-level flag anymore, only a count of flagged lessons within it)

**Student Summary** — the read-only page at `/class/:classId/student/:studentId` showing one student's current lesson (or "Not started"/"No lessons yet") in each subject, plus a list of that student's review flags grouped by subject. Reached only by clicking a student's name in the Class Board roster (right-click there is already "Remove student"). Distinct from the printable per-student Reports screen (#11): Student Summary is the deliberate growth point for future student-detail features and keeps its own data builder rather than sharing the report's, so the two can evolve independently (see [ADR-0009](docs/adr/0009-student-summary-gets-its-own-data-builder.md)). Its one editing control is removing a review flag; removals can be undone as a batch with a single "Undo review flag changes" button that disappears once the teacher navigates away. No other editing or click-through to subjects — those stay on the Class Board's Progress Cell.

**Unit** — a grouping of lessons within a subject's curriculum that share the same `unit` number on `LessonRow`. Not a stored entity: there is no `Unit` table or type, no unit-level metadata (name, description), and no way for a unit to exist with zero lessons. Grouping is computed client-side from the flat lesson list wherever the Curriculum page needs to display lessons by unit.

**Remove** — the soft-delete action for a Class Board entity (Student, Lesson, Subject): sets `deleted_at` on the row rather than destroying it, hiding the entity from the UI without erasing its data. Used consistently in user-facing labels and confirmation dialogs (`RemoveStudentDialog`, `RemoveLessonDialog`, `RemoveSubjectDialog`) — see [ADR-0010](docs/adr/0010-soft-deleted-lessons-join-the-unique-index.md) for how removal interacts with uniqueness constraints. Removing a Subject hides every Lesson within it and every student's progress/review flags in it, across the whole Class — the same pattern, just wider blast radius; no cascade write to child Lesson rows is needed since every page already derives its Lesson query from the already-filtered, not-deleted Subject list (see #188).
_Avoid_: Delete (implies permanent, destructive removal, which this isn't)

**Template** — a frozen, private snapshot of curriculum a teacher saves for reuse later. Copies the data at save time, so later edits to (or deletion of) the source Class or Subject never change a saved Template. Visible only to the teacher who saved it, never shared across teachers. Two scopes: Class Template and Subject Template. See [ADR-0015](docs/adr/0015-templates-reset-the-roster-not-archive-the-semester.md) for why this replaces the alternative of archiving a whole semester.
_Avoid_: Semester (the issue that requested this used "semester," but a Template isn't time-boxed — a teacher can reuse one mid-year, not just at term boundaries)

**Class Template** — a Template capturing every Subject (name and position) and its Lessons for an entire Class. Saved via a standalone action on the Class Board, not tied to deleting or replacing anything. Nothing loads a Class Template back onto a class yet — see [ADR-0016](docs/adr/0016-class-templates-ship-save-only.md).

**Subject Template** — a Template capturing one Subject's Lessons only (unit, lesson-in-unit, title, description) — not the Subject's name, since a new Subject is always named independently. Saved from the Subject's curriculum page. Loaded by picking it while creating a new Subject: this prefills the new Subject's name from the Template's name and populates its Lessons in one step (see [ADR-0016](docs/adr/0016-class-templates-ship-save-only.md)). The picker lists every Subject Template the teacher has ever saved, across all their Classes and Subjects, past or present.

**Bulk Generate** — a teacher action on the Curriculum page, triggered by a button next to "+ Add Lesson", that fills gaps in a fixed grid of unit 1 through N, lesson 1 through M within each unit (N and M given by the teacher, capped at 50 each). For every position in that grid without a live lesson, it creates one titled "Untitled" with an empty description; positions that already have a live lesson — or that fall outside the grid — are left untouched. A position occupied only by a soft-deleted lesson counts as empty and gets a fresh lesson, same as "+ Add Lesson" already allows; the old soft-deleted row is left alone, not restored (see [ADR-0013](docs/adr/0013-bulk-generate-fills-gaps-in-a-fixed-grid.md)). Commits immediately; a one-shot "Undo Bulk Generation" then soft-deletes every lesson the batch created, following the same lifecycle as Bulk Advance's undo — cleared by any other lesson-affecting action on the page, and lost on navigating away. Its modal is also the entry point for [AI Bulk Generation](#ai-bulk-generation), kept as a distinct feature reached via an "Auto-generate" toggle rather than a separate button (see [ADR-0019](docs/adr/0019-ai-bulk-generation-nests-inside-bulk-generate-modal.md)).
_Avoid_: "AI Bulk Generation" (a distinct feature — see below)

**AI Bulk Generation** — a teacher action, given an existing Subject and a curriculum name typed by the teacher (e.g. "Saxon Math 5/4"), that searches the web for that curriculum's public table of contents and proposes a full lesson list (unit, lesson-in-unit, title, description) with a variable lesson count per unit, discovered from real source content rather than a teacher-specified grid size. Reached via the "Auto-generate" button inside the Bulk Generate modal (kept distinct from [Bulk Generate](#bulk-generate) itself, which it swaps out rather than replaces — see [ADR-0019](docs/adr/0019-ai-bulk-generation-nests-inside-bulk-generate-modal.md)): clicking "Auto-generate" replaces the modal's manual Units/Lessons-per-unit form with a single curriculum-name input (blank by default, not pre-filled from the Subject's name) and a "Generate" button; a "Back" link returns to the manual form until "Generate" is clicked. Submitting sends the curriculum name to the server's AI web-search + generation endpoint (`POST /ai-bulk-generation`), which calls Anthropic's Claude API in two steps — search, then structured extraction — to produce the proposed lesson list (see [ADR-0018](docs/adr/0018-anthropic-claude-two-call-web-search-for-ai-bulk-generation.md)). On success, the proposal flows through the propose/diff/accept-decline/replace/undo mechanism (see #143) before anything commits, so it can replace lessons that already exist — unlike Bulk Generate, which only fills empty grid cells and commits immediately; what happens with the proposed list afterward is a separate concern, not part of this entry point. While the request is in flight, closing the modal or backing out requires confirming first, since (unlike Bulk Generate's instant local write) there's real async work to interrupt; once the request settles — success or a not-found/failure response — that guard is gone again.
_Avoid_: "Bulk Generate" (that's the unrelated fixed-grid, placeholder-only, immediate-commit action above)
